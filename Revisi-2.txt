[HIGH] 1.1 CSP Menggunakan 'unsafe-inline' untuk Script dan Style
─────────────────────────────────────────────────────────────────────
File: vercel.json (baris 20)
Masalah:
  - script-src mengandung 'unsafe-inline' → membuka celah XSS injection
  - style-src mengandung 'unsafe-inline' → memungkinkan injeksi CSS berbahaya
  - Meskipun ini SPA dan Tailwind butuh inline styles, 'unsafe-inline' pada
    script-src TIDAK DIPERLUKAN dan BERBAHAYA

  CSP saat ini:
    script-src 'self' 'unsafe-inline' https://va.vercel-scripts.com ...
    style-src 'self' 'unsafe-inline'

Dampak:
  - 'unsafe-inline' pada script-src secara efektif MEMBATALKAN proteksi XSS
    dari CSP. Jika ada celah injection di manapun, attacker bisa inject
    <script>alert('xss')</script> dan CSP tidak akan membloknya.

Rekomendasi:
  - HAPUS 'unsafe-inline' dari script-src
  - Gunakan nonce-based CSP atau hash-based CSP jika ada inline script
  - Untuk style-src, 'unsafe-inline' masih bisa ditoleransi karena Tailwind
    dan React membutuhkannya, tapi idealnya gunakan nonce juga
  - Referensi: https://web.dev/articles/strict-csp

  Contoh perbaikan script-src:
    script-src 'self' https://va.vercel-scripts.com https://*.vercel-insights.com https://static.cloudflareinsights.com;

  CATATAN: Perlu ditest bahwa semua fitur tetap berfungsi setelah penghapusan
  'unsafe-inline'. Jika ada inline <script> di root.tsx (JSON-LD), gunakan hash.

[HIGH] 1.2 dangerouslySetInnerHTML pada JSON-LD Tanpa Sanitasi
──────────────────────────────────────────────────────────────────
File: src/app/root.tsx (baris 59-77)
Masalah:
  - JSON-LD structured data menggunakan dangerouslySetInnerHTML
  - Meskipun datanya saat ini static/hardcoded, ini membentuk pattern yang
    BERBAHAYA jika kedepannya data diambil dari API/CMS
  - JSON.stringify TIDAK melakukan escaping untuk HTML context:
    Jika value mengandung </script>, browser akan menutup tag script

  Kode:
    <script
      type="application/ld+json"
      dangerouslySetInnerHTML={{
        __html: JSON.stringify({ ... }),
      }}
    />

Dampak:
  - Risiko XSS jika data JSON-LD nantinya bersumber dari input user/API
  - Pattern ini sering menjadi celah keamanan saat project berkembang

Rekomendasi:
  - Tetap gunakan JSON.stringify tapi tambahkan escaping untuk karakter
    berbahaya dalam context HTML:
    const safeJsonLd = JSON.stringify(data).replace(/</g, '\\u003c');
  - Atau pindahkan JSON-LD ke file .json terpisah yang di-serve sebagai static

  - Font sudah di-self-host (bagus!) ✓
  - font-display: swap sudah digunakan (bagus!) ✓

    <link rel="icon" ...>

    <link rel="preload" href="/fonts/inter-latin-400.woff2" as="font"
          type="font/woff2" crossOrigin="anonymous" />
    <link rel="preload" href="/fonts/crimson-text-latin-700.woff2" as="font"
          type="font/woff2" crossOrigin="anonymous" />

  - crossOrigin="anonymous" WAJIB untuk font preload, bahkan untuk same-origin

[MEDIUM] 2.4 IntersectionObserver Berulang di Setiap Section (DRY Violation)
──────────────────────────────────────────────────────────────────────────────
File: ProductSection.tsx, TechSection.tsx, RoadmapSection.tsx,
      TeamSection.tsx, DashboardSection.tsx
Masalah:
  - SEMUA 5 komponen section memiliki kode IntersectionObserver yang
    IDENTIK (copy-paste pattern):

    const [visible, setVisible] = useState(false);
    const sectionRef = useRef<HTMLElement>(null);

    useEffect(() => {
      const observer = new IntersectionObserver(
        ([entry]) => {
          if (entry.isIntersecting) setVisible(true);
        },
        { threshold: 0.1 }, // atau 0.15
      );
      const current = sectionRef.current;
      if (current) observer.observe(current);
      return () => {
        if (current) observer.unobserve(current);
      };
    }, []);

  - Kode yang sama di-copy-paste 5 kali

Dampak:
  - Melanggar prinsip DRY (Don't Repeat Yourself)
  - Jika ada bug di IntersectionObserver logic, harus diperbaiki di 5 tempat
  - Menambah boilerplate yang tidak perlu di setiap komponen

Rekomendasi:
  - Buat custom hook useInView:

    // src/hooks/useInView.ts
    import { useEffect, useRef, useState } from "react";

    export function useInView(threshold = 0.1) {
      const [visible, setVisible] = useState(false);
      const ref = useRef<HTMLElement>(null);

      useEffect(() => {
        const observer = new IntersectionObserver(
          ([entry]) => {
            if (entry.isIntersecting) setVisible(true);
          },
          { threshold },
        );
        const current = ref.current;
        if (current) observer.observe(current);
        return () => {
          if (current) observer.unobserve(current);
        };
      }, [threshold]);

      return { ref, visible };
    }

  - Penggunaan di komponen:
    const { ref, visible } = useInView(0.1);

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Project atma.biz.id telah mengalami PENINGKATAN SIGNIFIKAN sejak Revisi-1.
Dari 14 temuan utama Revisi-1, SEMUA telah ditangani dengan baik. Ini
menunjukkan komitmen tim terhadap kualitas kode.

Namun, dalam analisa mendalam Revisi-2 ini ditemukan 28 temuan yang terdiri
dari masalah yang BARU TERIDENTIFIKASI (bukan regresi). Fokus utama:

  1. SECURITY: CSP 'unsafe-inline' adalah kelemahan terbesar saat ini.
     Meskipun headers sudah ditambahkan, efektivitasnya BERKURANG karena
     unsafe-inline pada script-src secara efektif membatalkan proteksi XSS.

  2. CODE QUALITY: Duplikasi kode adalah tema utama — ErrorBoundary duplikat,
     IntersectionObserver duplikat, scrollTo duplikat, inline style animation
     yang berulang. Ini bukan bug, tapi technical debt yang akan menyulitkan
     maintenance kedepannya.

  3. PERFORMANCE: Font preload yang hilang dan gambar profil yang oversized
     mempengaruhi Core Web Vitals (LCP, FCP). Ini relatif mudah diperbaiki
     dengan impact besar.

  4. ACCESSIBILITY: Beberapa elemen masih gagal WCAG AA (kontras #333 dan #444),
     dan section/accordion kurang ARIA attributes.

Overall: Project sudah JAUH LEBIH BAIK dari kondisi Revisi-1. Dengan
menyelesaikan Batch 1-5, skor bisa naik dari 7.7 ke target 9.0+/10.
